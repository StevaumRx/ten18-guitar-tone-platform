# Project instructions

- Read README.md and docs/ROADMAP.md before changing architecture.
- Keep product assumptions explicit; do not invent requirements or gear specifications.
- Prefer small, reviewable changes and avoid unnecessary dependencies.
- Keep experimental code in experiments/ until approved for the application.
- Never commit credentials, real .env files, private customer data, or copyrighted audio without permission.
- Run npm run check and npm test for code changes; report any checks you could not run.
- Document meaningful architecture decisions in docs/DECISIONS.md.
- Do not imply that local tests or CI constitute deployment.
